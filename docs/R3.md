# R3：依据设备日志修改实际路径

用户 D1 日志确认：

- PROBE_D1_LOADED、PROBE_D1_UI_ATTACHED，诊断库在 iPhone 15 Pro Max / iOS 17.0 / TrollStore 上加载。
- 冷启动广告为 STAd.SplashAdViewController，并包含 SplashAdImageView、SplashAdSkipButton 等。
- 激励视频显示 BDARVLynxViewController / BDARRefactorLynxVideoWrappView。
- BDMannorRewardVideoManager 的三个方法仅记录 HOOK，没有记录 CALL。不能将它们当作这次广告的实际入口。
- D1 的 MISSING BDARewardedVideoAdBaseController 实际含义为所指定方法没有找到，不代表整个类不存在。新日志将区分类缺失和方法缺失。

没有将用户整段日志提交到公共仓库。

## 修改

1. 原包 SHA256 锁定，仅修改 SplashServiceManager 的展示资格判断函数与跳板，使正常调用方走原有不展示分支。这不是直接跳过 viewDidLoad 或删除广告窗口。
2. 移除 r1/r2 的八处等待和进度改动。本版不叠加已经失败的尝试。
3. 在已确认的 BDARVLynxViewController 上接入 JS/SDK 两种真实首帧回调。原回调仍执行，首次可见首帧后尝试调用 SDK 原有 videoBecomeInspired 方法一次。
4. 只有 SDK 自己设置 newLoadState 的有效标志 0x40 后，才调用原有 close。没有改写服务器响应，也没有修改账号会员状态。
5. 若 ABI、首帧、可见性或有效标志条件不满足，保留原广告流程并记录原因。复用控制器时重置单次状态。
6. 保留“日志 R3”导出按钮和安装名“汽水R3”，确认安装版本，必要时检查真实方法命中。

## 静态依据

- videoFirstFrame、videoFirstFrameSDK、videoBecomeInspired、close 返回 v16@0:8。
- newLoadState 返回 Q16@0:8，按 NSUInteger 读取。
- videoBecomeInspired 在 0x1006ee270 检查 bit 6，在函数尾设置该位；期间执行 SDK 决策和原有 delegate 回调。
- 视频内部请求及服务端听歌权益仍由原程序处理。有效标志不是服务器已发奖的证明。

## 测试与设备验证边界

CI 测试每个控制器仅尝试一次、未展示时不触发、没有有效标志时不关闭、重复回调不重复关闭，并检查日志钩子的参数转发。Apple SDK 编译 ARM64，校验原包、补丁位置、加载命令、签名、各 section 和其余资源。

实际冷启动/热启动是否无开屏、视频是否提前结束、完整歌曲播放与听歌权益是否获得，都需要真机反馈。R3 不是已经验证的“完整去广告版”。前置“看视频全天免费听”入口仍可能出现；本版针对视频等待与开屏展示。

如需反馈日志：覆盖安装后彻底退出重开，确认“日志 R3”，复现开屏与激励视频后导出 Qishui-Probe-R3.txt。关键事件为 R3_FIRST_FRAME_*、R3_INVOKE_EXISTING_videoBecomeInspired、R3_EFFECTIVE_SDK_FLAG、R3_CLOSE_EXISTING_SDK_FLOW，失败条件也会记录。

## R3.1：发布产物与设备日志不一致的排查

用户明确表示再次安装的是 R3，但导出的运行日志仍包含 PROBE_D1_LOADED、PROBE_D1_UI_ATTACHED 和旧版 MISSING 格式。不能仅凭这些标签断言用户安装了错误文件。

静态读取 GitHub R3 产物时，Info.plist 的 QSProbeBuild 为 R3，主程序依赖仅包含 QishuiR3.dylib，库中包含 R3 回调代码，两处开屏指令为预期值。这些证据和设备日志之间存在矛盾；目前不能确认原因是旧进程、安装更新未切换、日志文件来源，还是额外注入导致旧诊断类共存。

R3.1 保留业务修改，但作以下交付与身份修正：

- 安装构建号由原始 100212010 增至 100212041，保留 com.soda.music Bundle ID。
- 文件、库与日志标识分别为 R3.1、QishuiR31.dylib、R3_1_RUNTIME_LOADED。
- 将诊断及状态类、导出函数统一隔离为 QSR31 前缀，降低旧注入库共存时的 Objective-C 类名/全局符号冲突。
- 右上角导出按钮为“日志 R3.1”，文件名 Qishui-Probe-R3.1.txt。
- 启动记录实际 bundle 构建号、QSProbeBuild 与已加载的 Qishui/Probe 库文件名。只记录文件名和地址，不记录完整设备路径或账号数据。
- CI 在打包前检查编译产物含字面 R3.1 启动标识和隔离类名，禁止遗留 QSProbeInstaller 类名。

这是对矛盾的诊断修正，不是已确认的根因或去广告成功证明。
